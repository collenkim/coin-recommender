# Requirements — 추천 결과 적중 판별 및 학습 반영

## Intent Analysis Summary
- **User Request**: "추천한 코인이 예측 도달 %에 부합했는지 아닌지 그 다음 동작에 판별하고, 기록하고 이런 데이터도 학습해서 좀 더 정교하게 맞출수 있도록 로직을 추가하거나 수정해줘."
- **Request Type**: Enhancement / New Feature — 기존 3개 유닛 모두에 걸침
- **Scope Estimate**: Multiple Components (data-pipeline 데이터 재사용, analytics-backtest 신규 평가 로직, api-service 스케줄링+스키마+API)
- **Complexity Estimate**: Complex — 새 데이터 모델, 새 비즈니스 규칙, 기존 회고적 백테스트 로직과의 정합성 고려 필요
- **Depth Applied**: Standard/Comprehensive

## Code Investigation Findings (중요 — 설계 방향을 바꾸는 발견)
`src/backtest.py`의 `compute_signal_stats`는 매 추천 실행마다 그 코인의 **저장된 전체 1시간봉 이력을 처음부터 다시 스캔**해서, 같은 시그널(BR4/BR6)이 과거에 떴던 모든 시점을 찾아 그때의 실제 24시간 후 수익률을 평균냅니다. 캔들 수집은 매시 계속 진행되므로(Unit 1), **시간이 지나 새 캔들이 쌓일수록 이 스캔은 자동으로 더 많은 실측 데이터를 포함하게 됩니다** — 별도의 "라이브 추천 결과를 백테스트 풀에 주입"하는 코드 없이도, 기존 구조 자체가 이미 스스로 최신 데이터로 갱신되는 회고적 학습 메커니즘입니다.

즉, Q2=A("적중/실패 결과를 백테스트 샘플 풀에 누적 반영")가 요구하는 효과는 **이미 자동으로 일어나고 있습니다.** 새로 만들어야 하는 건 "미래 예측 정확도 개선 로직"이 아니라, **특정 시점에 실제로 추천했던 항목이 결과적으로 맞았는지 기록하고 조회 가능하게 만드는 것**입니다 (감사/추적 목적) — 이건 현재 전혀 없는 기능입니다: `recommendations` 테이블은 추천을 저장만 하고 이후 결과를 되짚어보는 로직이 없습니다.

## Clarifying Answers (from requirement-verification-questions.md)
| # | Question | Answer |
|---|---|---|
| 1 | "적중" 판별 기준 | 24시간 이내 어느 시점에서든 고가(high) 기준으로 임계값(4%) 도달 여부 (관대한 기준) |
| 2 | "학습"의 의미 | 적중/실패 결과를 기존 백테스트 샘플 풀에 누적 반영, 필터링 알고리즘 자체는 안 바뀜 — **위 발견에 따라, 이 효과는 candle 이력 누적을 통해 이미 자동으로 일어남. 신규 구현 범위는 "기록/추적"으로 좁혀짐** |
| 3 | 판별 실행 시점 | 기존 시간당 스케줄러(매시 5분) 안에서 함께 처리 |
| 4 | 과거 기록 소급 판별 | 함 — DB에 필요한 캔들 데이터가 남아있는 범위까지 소급 |
| 5 | API 노출 | `GET /recommendations` 확장 (기존 엔드포인트 유지, 과거 판별 결과 포함) |

## Functional Requirements
- FR-L1: 각 추천(run_time, market)에 대해, 추천 시점 기준 24시간이 지나면 실제로 목표 수익률(4%)에 도달했는지를 판별한다 — 판별 기준은 24시간 구간 내 고가(high) 기준 (Q1=B).
- FR-L2: 판별 결과(적중 여부, 실제 24시간 후 종가 기준 수익률, 판별 시각)를 해당 추천 레코드에 영속 저장한다.
- FR-L3: 판별은 기존 시간당 스케줄러 실행에 포함되어, 아직 판별되지 않았고 24시간이 지난 추천 건들을 매 회 처리한다 (Q3=A).
- FR-L4: 이 기능 배포 이전에 저장된 과거 추천 기록도, DB에 필요한 캔들 데이터가 남아있는 한 소급 판별한다 (Q4=B).
- FR-L5: `GET /recommendations`를 확장해 판별 결과를 조회할 수 있게 한다 — 기본 호출(파라미터 없음)은 기존과 동일하게 최신 1회차만 반환(하위 호환), 조회 개수를 지정하면 최근 N회차까지 반환하고 각 추천 항목에 판별 결과(적중 여부/실제 수익률, 미판별이면 null)를 포함한다 (Q5=A 취지 반영).
- FR-L6 (명시적 비범위): `expected_return`/`n`/`hit_count` 계산 로직(`compute_signal_stats`) 자체는 변경하지 않는다 — 위 발견에 따라 이미 자동으로 최신 데이터를 반영하고 있음.

## Non-Functional Requirements
- NFR-L1 (Consistency): 판별에 쓰이는 "24시간 후 수익률" 계산은 기존 백테스트 표본과 동일한 방식(entry_close 대비 24봉 뒤 close)을 재사용해 로직 중복/불일치를 피한다.
- NFR-L2 (Resiliency, RESILIENCY-10 연장): 특정 추천 건의 판별이 실패(캔들 데이터 부족 등)해도 다른 건 판별에 영향 주지 않고, 다음 회차에 재시도한다 (판별 안 됨 상태 유지).
- NFR-L3 (Schema Evolution): 이미 배포된 DB(`recommendations` 테이블에 기존 데이터 존재)에도 안전하게 적용되는 마이그레이션(컬럼 추가) 방식을 사용한다.

## Out of Scope
- 필터링/스코어링 알고리즘 자체의 적응형 변경 (Q2=B 미선택).
- 신규 별도 엔드포인트 (Q5=B 미선택, 기존 엔드포인트 확장으로 대체).
- ML 모델 학습, 별도 학습 파이프라인 — 요청하신 "학습"은 기존 회고적 백테스트 재스캔 메커니즘으로 이미 충족됨 (위 발견 참조).
