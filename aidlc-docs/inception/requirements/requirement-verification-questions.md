# Requirements Clarification Questions — BTC/ETH 강세장 구분 문구 출력

## 먼저 확인한 현재 상태 (질문의 전제)

- **지금도 "레짐" 개념은 이미 있습니다.** `src/backtest.py`의 `build_regime_series()`가 BTC **4시간봉**만 보고 `strong_bull`(30일 수익률 > +20%) / `rebound`(30일 수익률 <= 0 이면서 30일 저점 대비 +10% 초과 **AND** 200일선 위) / `None`(그 외) 3가지로 판정합니다.
- **이 레짐은 "진입 게이트"입니다.** `None`이면 `generate_recommendations()`가 추천을 0건으로 만듭니다. 즉 지금 레짐은 표시용이 아니라 **매매를 막는 스위치**이고, `MIN_HIT_RATE=45%`·`n>=10` 같은 수치는 전부 **이 게이트가 켜진 구간에서만 측정된 값**입니다.
- **ETH는 현재 어디에도 안 쓰입니다.** 레짐은 BTC 단독이고, ETHUSDT는 오히려 추천 후보에서 제외돼 있습니다(`_BINANCE_EXCLUDED_MARKETS`).
- **일봉/주봉/월봉은 수집하지 않습니다.** DB에 있는 건 후보 코인 1시간봉과 BTC 4시간봉뿐입니다.
- **알림 문구에 레짐이 안 들어갑니다.** `notifier._format_message()`는 추천 0건일 때 `"이번 회차 추천 없음"`만 보냅니다 — 게이트가 닫혀서 0건인지, 열렸는데 통과한 코인이 없어서 0건인지 사용자가 구분할 수 없습니다 (2026-08-13 진단에서 이미 기록된 문제).

아래 4개가 구현 방향을 가르는 지점입니다.

## Question 1
새로 만들 "약상승장 / 강상승장" 구분을 **어디까지** 적용할까요?

A) **문구(표시) 전용.** 알림·API에 현재 시장 상태를 문장으로 덧붙이기만 하고, 추천을 낼지 말지 결정하는 기존 레짐 게이트(BR20)는 **그대로 둔다.** — 기존 백테스트 수치(적중률 45% 문턱 등)가 측정된 조건이 안 바뀌므로 발표하는 확률과 실제가 어긋나지 않음

B) **게이트까지 교체.** 새 약/강상승장 판정이 진입 여부까지 결정하게 바꾼다. — 이 경우 기존 5년 실측 근거(강한상승 59.7% / 반등 55.5%)는 **다른 조건에서 나온 숫자가 되어 무효**가 되므로, 새 기준으로 백테스트를 다시 돌려 재검증하는 작업이 함께 필요

## Question 2
"일, 주, 월 데이터"를 어떻게 읽을까요?

A) **1일 / 7일 / 30일 수익률** 세 구간의 모멘텀. — 이미 수집 중인 캔들로 바로 계산 가능, 추가 데이터 수집 없음

B) **일봉 / 주봉 / 월봉 캔들** 각각의 추세(예: 각 봉이 자기 이동평균 위인가, 직전 봉 대비 상승인가). — 바이낸스에서 `1d`/`1w`/`1M` 봉을 새로 수집해야 함. 월봉은 5년 = 60개뿐이라 통계적 판단 근거로는 얇음

## Question 3
BTC와 ETH 두 개를 어떻게 하나의 판정으로 합칠까요?

A) **둘 다 강해야 강상승장** (AND). 하나만 강하면 약상승장. — 가장 보수적

B) **각각 따로 표시.** "BTC 강상승 / ETH 약상승"처럼 두 줄로 보여주고 종합 판정은 하지 않는다

C) **BTC 우선, ETH는 보조.** BTC 모멘텀으로 판정하고 ETH는 문구에 참고 정보로만 붙인다

## Question 4
약상승 / 강상승을 가르는 **임계값**은 어떻게 정할까요?

## 답을 기다리지 않고 적용할 가정 (반대하시면 말씀해 주세요)

- 레짐 문구는 **추천 0건일 때도** 알림에 포함합니다. 위에 적은 "게이트가 닫혀서 0건인지 알 수 없다"는 기존 문제를 같이 해소하기 위함입니다.
- 문구는 텔레그램/디스코드/슬랙 알림과 `GET /recommendations` 응답 **양쪽**에 나갑니다 (같은 정보가 채널마다 다르면 안 됨).
